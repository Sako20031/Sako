# Протоколы и препараты: загрузка и верификация

## Текущее содержимое

`shared/seed_protocols.json` — библиографические метаданные 7 реальных опубликованных
документов (NEWS2, ESC ACS 2023, ERC 2021, AHA 2020, WAO 2020, EAACI 2021, ATLS 10).
Внесены по знаниям разработчиков **без онлайн-проверки** (в среде не было доступа к сайтам
издателей), поэтому у всех статус `unverified`, `last_verified = null`, клинического текста нет.
Часть из них, вероятно, уже заменена новыми редакциями.

**Протоколов Министерства здравоохранения РК в базе нет.** Пока администратор их не
загрузит и не отметит проверенными, отчёты показывают:
«В базе знаний нет проверенного применимого протокола…».

**Препаратов в базе нет.** Справочник показывает «Проверенных записей пока нет».

Где искать официальные документы РК (адреса нужно проверить): портал клинических протоколов
МЗ РК, Республиканский центр развития здравоохранения (РЦРЗ), Казахстанский национальный
лекарственный формуляр.

## Загрузка протокола (роль admin)

```bash
curl -X PUT https://<host>/api/admin/protocols/kz-acs-2024 \
  -H 'content-type: application/json' -H 'x-rescue-client: 1' -b cookies.txt \
  -d '{"slug":"kz-acs-2024","title":"…","issuer":"Министерство здравоохранения РК",
       "version":"…","publication_date":"2024-01-01","jurisdiction":"KZ",
       "source_url":"https://…","language":"ru","topics":["acs","ecg"],
       "sections":[{"title":"…","summary":"…"}],"status":"current"}'
```

- `status: current` требует `source_url`; сервер ставит `last_verified` и `verified_by`.
- Каждое изменение увеличивает `revision` и сохраняет полный снимок в `reference_revisions`
  (`GET /api/admin/revisions/{id}`), действие пишется в аудит.
- Темы (`topics`) связывают документ с задачами: `ecg, acs, arrhythmia, resuscitation`
  (ЭКГ), `anaphylaxis, skin` (кожа), `trauma, wound, burn` (раны), `triage` (симптомы).
- Заменённую редакцию переводите в `superseded`, а не удаляйте.

## Загрузка препарата

```json
PUT /api/admin/medications/epinephrine
{"generic_name":"epinephrine","brand_names":[],"drug_class":"…",
 "fields":{"indications":"…","contraindications":"…","routes":"…","dosing":"…"},
 "source_title":"…","source_url":"https://…","protocol_version":"…","status":"current"}
```

- Поле `dosing` без `source_url` и `source_title` отклоняется.
- Доза показывается пользователю только если `status = current` и есть источник; иначе
  «Дозировка не проверена».
- Отсутствующие поля отображаются как «нет данных» — ничего не дополняется моделью.

## Правило верификации

Переводить документ в `current` может только ответственный сотрудник после сверки с
первоисточником. Дата и логин фиксируются автоматически. Рекомендуется ежеквартальный
пересмотр: документы с `last_verified` старше года отмечать на проверку.
