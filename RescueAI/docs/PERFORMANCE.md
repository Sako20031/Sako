# Производительность: измерения

**Ни одного измерения на реальном iPhone не проводилось** — в среде разработки нет устройств
Apple и WebKit. Ниже — измерения в Chromium с эмуляцией экрана iPhone и искусственным
замедлением. Они показывают порядок величин и ловят регрессии, но не заменяют проверку
в Safari на реальных устройствах (особенно на старых моделях).

## Размер пакета (`npm run build`, 2026-10-20)

| Что | gzip |
|---|---|
| Стартовый JS (главная + Preact + ru + роутер) | **20,3 КБ** (бюджет 60 КБ проверяется сборкой) |
| CSS | 1,9 КБ |
| Самый крупный ленивый модуль (kk-словарь) | 5,8 КБ |
| Экран анализа изображения | 2,4 КБ (+ worker 1,2 КБ) |
| Передано по сети при холодной загрузке главной (сервер с gzip) | 20,9 КБ JS |

## Холодная загрузка главной (Playwright, `e2e/app.spec.ts`)

Условия: Chromium 1194, эмуляция iPhone SE (375×667) и iPhone 13 (390×844), замедление CPU ×4,
сеть 300 мс RTT / 1,6 Мбит/с вниз / 750 кбит/с вверх, бэкенд на той же машине.

| Профиль | FCP | LCP | DOMContentLoaded |
|---|---|---|---|
| iPhone SE (эмуляция) | 816 мс | 816 мс | ~770 мс |
| iPhone 13 (эмуляция) | 828 мс | 828 мс | ~775 мс |

## Отзывчивость и память

- Переходы между экранами (Симптомы, Справочник, Препараты, Неврология и обратно):
  **0 long tasks** (> 50 мс) без замедления CPU.
- JS-heap (Chromium `performance.memory`) при выборе фото 1600×1000: до — 2,6 МБ,
  с открытым экраном — 3,3 МБ, после ухода и GC — 2,4 МБ (worker завершается, object URL
  освобождается). Память декодированных изображений и GPU этим не измеряется.
- Горизонтальной прокрутки нет ни на одном проверенном экране при ширине 375 и 390 px.

## Как повторить

```bash
cd frontend && npm run build && npx playwright test     # результаты: frontend/e2e-results/*.json
```
