# ИИ-провайдеры

## Состояние

| Провайдер | Код | Проверено |
|---|---|---|
| `none` (по умолчанию) | `services/ai/base.py::UnavailableProvider` | да: приложение честно показывает «ИИ-анализ недоступен» |
| Claude (Anthropic Messages API) | `services/ai/anthropic_provider.py` | только на подменном HTTP-транспорте (формат запроса, разбор ответа, ошибки, отказ, повторы). **Реальный вызов API не выполнялся**: в среде разработки не было ключа и доступа к сети. Качество медицинских ответов не оценивалось. |

Все задачи (ЭКГ, кожа, раны, симптомы) используют один адаптер, но **разные системные
инструкции** (`services/ai/prompts.py`) и общие пост-правила безопасности. Отдельные
специализированные модели (ЭКГ-классификатор, дерматологическая модель) не подключены.

## Включение Claude

```
RESCUE_AI_PROVIDER=anthropic
RESCUE_ANTHROPIC_API_KEY=<ключ из console.anthropic.com>   # только на сервере
RESCUE_AI_MODEL=claude-opus-5-5
RESCUE_AI_EFFORT=high
RESCUE_AI_TIMEOUT_SECONDS=90
RESCUE_AI_MAX_RETRIES=2
RESCUE_AI_EXTERNAL_IMAGES_AUTHORIZED=false   # true только после юридического согласования
```

При `false` работает только текстовый анализ симптомов; анализ изображений возвращает
`unavailable / external_images_not_authorized`, изображения провайдеру не отправляются.

## Параметры запроса

- Модель `claude-opus-5-5`, adaptive thinking, `output_config.effort` из настроек.
- Структурированный вывод: `output_config.format = json_schema` по схеме `AIFindings`
  (все объекты закрыты, все поля обязательны), затем повторная проверка Pydantic.
- Серверный fallback при отказе классификатора безопасности: бета `server-side-fallback-2026-07-01`,
  `fallbacks: "default"` — Anthropic сам выбирает резервную модель по категории отказа.
  Фактическая модель записывается в `Analysis.model`. Если отказали все — статус `refused`.
- Таймаут и число повторов SDK (повторяет 408/409/429/5xx и сетевые ошибки) — из настроек.
- Ошибки сопоставлены статусам: таймаут, 401, 429, 400, прочие HTTP, сеть → `failed` с кодом;
  `max_tokens` или невалидный JSON → `invalid_output`.

## Что передаётся провайдеру

| Передаётся | Не передаётся |
|---|---|
| Копия изображения для анализа (без EXIF, уменьшенная) — только при `EXTERNAL_IMAGES_AUTHORIZED=true` | `patient_ref`, имя, ID пользователя, ID вызова |
| Клинический контекст, введённый в форме анализа: признаки, витальные, ответы, возраст, пол, локализация, заметки | Сохранённые оригиналы, история других вызовов |

Свободные поля (заметки, жалоба) могут содержать идентифицирующие данные, если их туда
вписать. Инструктируйте персонал не вводить ФИО и ИИН в эти поля.

Политика хранения данных у Anthropic зависит от договора организации (стандартные условия,
zero-data-retention и т.п.) и в рамках этой работы **не проверялась**. Перед включением
изображений её нужно проверить и зафиксировать в DPA.

## Добавление другого провайдера

Реализуйте протокол `AIProvider` (`name`, `async analyze(AIRequest) -> AIResult`, `health()`)
и подключите его в `services/ai/registry.py`. Обязательные требования: ответ валидируется
схемой `AIFindings`; любой сбой — не `completed`; ключи только на сервере; не отправлять
`patient_ref`. Тесты провайдера пишутся на подменном транспорте, как `tests/test_anthropic_provider.py`.
