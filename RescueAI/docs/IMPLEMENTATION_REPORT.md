# Отчёт о реализации (2026-10-20)

## Что работает (проверено тестами)

- **PWA для iPhone** на трёх языках (русский, казахский, английский), светлая и тёмная тема,
  крупные элементы управления, без анимаций. Главная с прямым доступом к ЭКГ, симптомам,
  сыпи, ранам, экстренным алгоритмам, препаратам, справочнику, неврологии.
- **Мгновенные экстренные предупреждения** по отмеченным признакам и витальным показателям —
  локально, без сети и без входа, до любой загрузки. Одни и те же правила на сервере и в браузере.
- **ЭКГ / сыпь / раны** — три отдельных сценария: опасные признаки, клинический контекст,
  камера или файл (PDF только для ЭКГ), поворот, обрезка, быстрая проверка качества в Web Worker,
  загрузка с прогрессом и отменой, фоновый анализ, отчёт A–G, проверка медработником
  с историей ревизий и неизменным исходным ответом ИИ.
- **19 сценариев симптомов** и неврологический модуль (признаки инсульта, время «последний раз
  здоров» с предупреждением о его значимости), текстовый ИИ-анализ.
- **Карта вызова**: все поля необязательны, пустое = неизвестно; метки источника
  (введено / голос / ИИ / подтверждено); удаление вместе с анализами и файлами.
- **Помощник документации**: черновик только из введённых и проверенных данных, без
  придуманного осмотра; экспорт (копирование текста) только после проверки.
- **Справочник протоколов** с поиском, статусами и версиями; **справочник препаратов**
  без единой непроверенной дозы; **офлайн-пакет** по запросу пользователя.
- **Бэкенд**: аутентификация (bcrypt, httpOnly-cookie), роли, CSRF-защита, проверка файлов
  по содержимому, лимиты, rate limiting, идемпотентность, аудит без клинического текста,
  срок хранения с очисткой, миграции Alembic, структурированные ошибки без данных пациента.
- **Адаптер Claude** со строгой JSON-схемой, серверным fallback при отказе, таймаутами,
  ограниченными повторами и сопоставлением всех ошибок статусам «не выполнено».
- **Без ИИ-ключа** приложение показывает ровно: «ИИ-анализ сейчас недоступен. Используйте
  проверенный медицинский справочник и применимый экстренный протокол.»

## Что протестировано

| Набор | Количество | Результат |
|---|---|---|
| Бэкенд, pytest (API, auth, загрузки, безопасность, опасные клинические сценарии, провайдер на подменном транспорте, общие кейсы сортировки) | 69 | все прошли |
| Фронтенд, vitest (логика сортировки, полнота ru/kk/en, сеть: дедуп/повторы/отмена, качество фото, UI, доступность axe, переключение языка) | 32 | все прошли |
| E2E, Playwright, эмуляция iPhone SE и iPhone 13 в Chromium (навигация, экстренный чек-лист без входа, загрузка ЭКГ → честное «недоступно», неверный файл, вызов, офлайн-справочник без сети, освобождение памяти, производительность) | 16 | все прошли |

Сценарии опасных сбоев из ТЗ покрыты тестами: размытая ЭКГ при сбое ≠ норма; неизмеренные
витальные ≠ норма; угроза дыхательным путям не ждёт анализа фото; «спокойная» сыпь не
перекрывает тяжёлые симптомы; фото раны не исключает глубокую травму; сбой ИИ не даёт
результата; нет протокола → нет выдуманной ссылки; нет веса ребёнка → нет дозы (расчёта доз
нет вообще); расхождение ИИ и признаков → требует внимания.

Миграция Alembic проверена вручную: `alembic upgrade head` на пустой SQLite создаёт все 9 таблиц.
На PostgreSQL миграции не запускались.

**Прохождение тестов не означает клинической безопасности.**

## Что не сделано / неполно

- **Реальный вызов ИИ не выполнялся**: в среде не было ключа и сети. Качество медицинских
  выводов Claude по ЭКГ, сыпи и ранам **не оценивалось**.
- Специализированные модели (ЭКГ-классификатор на PTB-XL/PhysioNet, дерматологическая) не
  подключены; извлечение сигнала ЭКГ, определение сетки, калибровки и отведений не реализованы
  как отдельные алгоритмы — их выполняет мультимодальная модель, без валидации.
- Коррекция перспективы ЭКГ не реализована (только поворот и обрезка).
- Протоколов МЗ РК и препаратов в базе нет; метаданные 7 международных документов не проверены.
- Казахский перевод выполнен разработчиками — нужна проверка носителем-медиком.
- Голосовой ввод: Web Speech API, без серверного распознавания; поддержка казахского зависит
  от браузера; в Safari работает нестабильно (есть подсказка про диктовку клавиатуры).
- Офлайн-черновики вызовов не сохраняются (данные пациента не хранятся на телефоне).
- Нет смены/сброса пароля в интерфейсе, MFA, серверного отзыва сессий, CSP, push-уведомлений.
- Нет экрана администратора в интерфейсе (справочник и пользователи — через API/CLI).
- Фоновые задачи в процессе веб-сервера; для масштабирования нужна очередь.
- Dockerfile не собирался (Docker недоступен в среде).
- Нативное SwiftUI-приложение не делалось (обоснование — ARCHITECTURE.md).

## ИИ-провайдеры

| Провайдер | Статус |
|---|---|
| `none` | активен по умолчанию |
| Claude (`claude-opus-5-5`) | реализован; нужен `RESCUE_ANTHROPIC_API_KEY`; изображения — дополнительно `RESCUE_AI_EXTERNAL_IMAGES_AUTHORIZED=true` |

Функции, требующие учётных данных: ИИ-анализ ЭКГ, сыпи, ран и симптомов. Всё остальное
(чек-листы, сортировка, карты вызовов, справочник, документация, офлайн) работает без них.

## Проверенные медицинские источники

**Ни одного.** Все записи — `unverified`. Правила сортировки — черновик (пороги из NEWS2,
не протокол РК).

## Измерения производительности

См. [PERFORMANCE.md](PERFORMANCE.md): стартовый JS 20,3 КБ gzip; FCP ≈ 0,8 с в Chromium-эмуляции
iPhone при CPU ×4 и медленной сети; 0 long tasks при навигации. Реальные iPhone не измерялись.

## Перед клиническим использованием

1. Клинический руководитель утверждает `shared/triage_rules.json`, чек-листы 19 сценариев
   и тексты предупреждений на трёх языках.
2. Загрузка и верификация действующих протоколов МЗ РК и формуляра препаратов.
3. Оценка ИИ на репрезентативных, лицензированных наборах данных (ЭКГ-фото, кожа, раны,
   в т.ч. разные типы кожи и условия съёмки) с заранее определёнными метриками; сравнение
   с врачами; анализ ошибок, особенно пропусков опасных состояний.
4. Проспективное пилотирование в режиме «только наблюдение» без влияния на решения.
5. Юридическая оценка: статус медицинского изделия (программное обеспечение) в РК,
   регистрация, требования к персональным и медицинским данным, DPA с ИИ-провайдером.
6. Тестирование на реальных iPhone (включая старые), в Safari, на мобильных сетях.
7. Тест на проникновение и закрытие пунктов из SECURITY.md.
8. Проверка казахского перевода носителем-медиком.
9. Обучение персонала; процесс сообщения о неверных результатах ИИ и их разбора.
